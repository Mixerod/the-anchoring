# FLOW-0001: Adopting The Anchoring in a new repository

## Journey

1. **Bootstrap (`kb init`)**:
   - Developer or agent runs `npx the-anchoring init` (or `kb init`).
   - The tool inspects the workspace, detects existing ADR directories, source folders, and symbol indexes, and writes `anchoring.config.json`.
   - Generates the `.anchor/` directory tree with `.gitkeep` files and template documents (`0000-template.md`).
   - Prints instructions for setting up the three gates (Stop hook, pre-commit hook, CI step).

2. **Initial Verification (`kb verify`)**:
   - Running `npx kb verify` validates that all templates are skipped and the repository starts clean with `0 entities, 0 anchors`.

3. **Authoring Intent Documents**:
   - The team or agent records architectural decisions in `docs/adr/`, linking them to code with `governs: [file:path/to/file.ts]`.
   - Invariants (`INV-`), flows (`FLOW-`), and work items (`W-`) are authored with machine-checkable anchors.

4. **Querying Why and Context**:
   - `kb why <file>` inspects why code exists and surfaces governing ADRs, flows, invariants, and prior touches.
   - `kb ctx <W-id>` provides progressive context disclosure before starting work on a task.

5. **Completing Work (`kb done`)**:
   - `kb done <W-id>` checks `git diff` against intent graph declarations and reports missing touches or unlinked changes before committing.
