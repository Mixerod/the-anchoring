# INC-0004: Every generated architecture checker matched nothing

## What happened

For the whole life of the `architecture` block, `kb guards` generated files that enforced
nothing, and every gate said so was fine.

`parseArchitecture` normalised each layer path by appending a trailing slash. That is right
for a directory and wrong for a file, and this repository declares its layers as files. So
every emitted matcher became `src/render.ts/` — a path no file on any filesystem can have.

Three independent confirmations, all run before any fix:

```
$ npx eslint --print-config src/verify.ts
  max-lines, max-lines-per-function, no-restricted-globals:  absent

$ # src/promote.ts (domain) importing src/render.ts (app), a direct
$ # layer-domain-must-not-import-app violation with no cycle involved
$ npx depcruise src
  no dependency violations found (68 modules, 343 dependencies cruised)   exit 0

$ npx kb guards --check
  anchoring.depcruise.cjs: ok
  anchoring.guards.mjs: ok
```

`max-lines`, `max-lines-per-function`, the pure-layer import ban and the entire dependency
matrix were inert. `no-circular` was the only live rule, which is why nothing ever looked
wrong: the one gate that could still speak kept speaking, and its silence about everything
else read as health.

## The second layer

Fixing the paths exposed a second, independent silencing. `eslint.config.js` composed the
generated fragment as `...anchoringGuards` and then declared hand-written blocks *after* it.
ESLint flat config does not merge rules: for a given file, a later object naming a rule
replaces the earlier one entirely. Two generated rules were being discarded without a word.

```
$ # in src/brief.ts, a pure-domain module
$ cat >> src/brief.ts <<'X'
import { request } from 'node:https'
import { createHash } from 'node:crypto'
X
$ npx eslint src/brief.ts
  (nothing)
```

`node:http`, `node:https` and `node:crypto` are all declared in `impureImports`, and none of
the three was enforced anywhere. The "pure core" could open a socket. The ban on constructing
a `Date` was lost the same way.

## The third thing it exposed

With the layer rules alive, `depcruise` found violations in *both* directions between domain
and infra — 11 one way, 9 the other — so no ordering could be green. Six modules named as
pure domain (`verify`, `done`, `ask`, `why`, `ctx`, `owners`) read the filesystem through
`loader.ts`. They passed the ban on `node:fs` by importing the module that imports it: one
hop around the rule.

## Why it survived

Each mechanism that should have caught this was checking the wrong thing.

- `kb guards --check` compares the generated file against the generator's own output. Both
  sides were wrong in the same way, so it agreed with itself.
- `guards.test.ts` asserted what the generator *emitted*. The emitted text was exactly as
  designed; the design produced patterns that matched nothing.
- `invariants.test.ts` ran ESLint for real, but on `src/dummy.ts`, and passed because the
  *hand-written* block covered it — the block that was overriding the generated one.

Nothing anywhere asserted that a rule the tool generated was in force on a real file.

## Verdict

`silent-gate`, and local in every respect: this repository wrote the generator, the
normaliser, and the ESLint composition.

## What changed

- A file path keeps no trailing slash; a file pattern is anchored with `$`.
- Project-wide rules key off `governedPaths` rather than the enumerated layer paths, so a
  file added before it is registered in the matrix is still governed.
- The six orchestrators are declared `app`, and `infra` sits above `domain`, because an
  adapter depends on the domain it adapts. `INV-PURE-CORE` now covers the set that is
  actually pure.
- `ioExemptions`, `restrictedSyntax` and `ioMessage` move into `anchoring.config.json`, so
  the host's ESLint file declares no rule the generator owns and the two compose instead of
  colliding.
- `maxFunctionLinesBaseline` records the 16 files already over the limit at their current
  worst, pinned to the line by a test, so the debt can only shrink.
- `guards-live.test.ts` asserts what ESLint **applies**, not what the generator emits.

## The rule this pays for

A generated rule that nothing verifies is a claim, not a check. The test that matters is not
"does the generator emit the right text" but "is this rule in force on a real file" — and it
belongs next to every generator that emits configuration for somebody else to compose.

Silence must be earned. Three gates were quiet here for the same reason: each was asking a
question it could answer without touching the thing that was broken.
