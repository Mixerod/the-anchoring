# INC-0005: `kb pack check --strict` failed a clean repository for every pack it had not adopted

## Impact

Any repository that adopted one pack while a second existed would fail CI on
`kb pack check --strict`, reporting every file of every *unadopted* pack as `missing`. The
repository would be entirely correct; the gate would be wrong.

Shipped in 0.2.0. It never fired because the tool shipped exactly one pack, and one pack is
always adopted or the command is not being run. The five `systems-*` packs of W-22 made a
second case exist, and the failure appeared on the first run.

## Cause

`src/cli-pack.ts`, in the branch that checks every pack:

```js
const hasAny = pack.files.some((f) => io.readFile(f.basename) !== undefined || true)
if (hasAny) packsToCheck.push(pack)
```

Two defects in one line. `|| true` makes the predicate unconditionally true, so the filter it
was written to perform never happened. And `f.basename` is not a path a repository contains —
the file lives at its *destination* (`.anchor/doctrine/x.md`), so even without `|| true` the
read would have returned `undefined` for every file and the filter would have excluded
everything instead.

Both halves were wrong, in opposite directions, and they cancelled: the intended behaviour was
never delivered and nothing observable differed while one pack existed.

## Why nothing caught it

The adoption filter had no test, because with one pack there was no input that distinguished a
working filter from a broken one. Every test seeded `discipline` and then checked it. The
suite could not have failed.

This is the shape the repository already has a rule for — a mechanism that can never say "no"
reports nothing useful until a second case arrives — and the rule was not applied to the
`--strict` exit code of this command.

## Fix

`isAdopted` moved into `src/pack.ts` as a pure function taking `read` as an argument, so it is
testable with no filesystem, and it resolves each file's destination path. `kb pack check`
now checks adopted packs and prints one line naming the packs it declined to check, so the
filter's rejections are visible rather than inferred.

## What generalises

- **A boolean expression ending in `|| true` is a disabled check.** It should be as suspicious
  in review as a commented-out assertion, and it is much harder to see.
- **A filter with one input has not been tested.** The test that matters is the one where it
  must exclude something, and until a second pack existed that test could not be written. It
  exists now.
