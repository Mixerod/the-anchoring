# INC-0003: A pack shipped an invariant but not the checker its anchor named

## What happened

`kb pack add discipline` in a freshly initialised repository turned a clean corpus into a
failing one:

```
error  INV-SECRETS-NO-LITERALS · enforced_by
       anchor `file:scripts/anchoring-scan-secrets.mjs` — no such file
kb verify: 1 error(s), 0 warning(s)      exit 1
```

The first thing an adopter is invited to do broke the gate they had just installed. Nothing
in this repository noticed, because here the file existed.

## Root cause

The pack format had three kinds — `invariant`, `hazard`, `doctrine` — and no way to carry
code. `INV-SECRETS-NO-LITERALS` was written with `enforced_by: file:scripts/anchoring-scan-secrets.mjs`,
and the script it names was hand-written into this repository only. No code generated it:
not `planGuards`, not `planPack`. `templates/packs/discipline/` never contained it.

So the invariant travelled and its checker did not. `docs/PLAN-LAYER4.md` §A.8 had asked for
a *generated* script; the document half was built and the generation half was not.

This is `INC-0001`'s mechanism wearing different clothes — correct in the checkout, broken
when installed elsewhere — and it was found the same way: by installing into a real
repository rather than by any check inside this one.

## Prevention

`PackFile` gains a `script` kind, seeded to `scripts/` — repo-relative and outside `kbRoot`,
because a checker is code the adopter runs and the `enforced_by:` anchors are written that
way. `src/pack-source.ts` reads a pack's `scripts/` directory alongside its markdown.

Two details were load-bearing and are covered by tests, not by comments alone:

- A `.mjs` cannot carry an HTML comment, so `headerStyleFor` picks `//` for scripts.
- A shebang must remain the first line, so the header is written below it. `renderPackFile`
  and `stripPackHeader` are exact inverses; if they were not, a seeded script would hash
  differently from its own header and report `stale` on every run forever.

Verified in a fresh adopter: `kb pack add discipline` then `kb verify --strict` →
`clean (3 entities, 1 anchors)`, exit 0. The seeded scanner runs, exits 0 on a clean tree,
exits 1 on a planted `AKIA…` literal, and prints the matching pattern rather than the value.

## What is still not guarded

There is no check that a pack's `enforced_by:` anchors resolve *within the pack* before it
ships. This defect was found by an audit that installed the pack, not by `kb verify`. The
general form — *a pack must be self-contained: every anchor it seeds must point at something
it also seeds, or at the adopter's own code* — is worth a checker, and does not have one.

That guard, plus the one named in `INC-0001` (a gate must account for what it examined),
are now the two known gaps of the same shape: things that are only true because nobody has
tested them from outside.
