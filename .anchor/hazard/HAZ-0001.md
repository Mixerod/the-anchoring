# HAZ-0001: The CLI checked nothing and exited 0 when installed as a package

## What happened

The first adopter installed this package and ran `kb verify --strict` against a corpus of
107 entities. It printed nothing and returned exit code 0.

Nothing was verified. The gate was green because it had not run, and no output distinguished
that from a clean corpus — the two look identical to CI, to a pre-commit hook, and to a
reader.

This is the worst failure shape a gate has. A gate that fails is noisy and gets fixed. A
gate that passes without checking removes the suspicion that would have caught the problem,
which is the whole reason it was installed.

## Root cause

`src/cli.ts` decided whether it was being invoked directly by comparing `process.argv[1]`
with `import.meta.url` literally.

Developing this repository, the CLI runs as `tsx src/cli.ts`, where those two resolve to the
same file and the comparison holds. Installed as a package they do not: a package manager
puts a **symlink** at `node_modules/<pkg>`, and Node resolves an ESM specifier to its real
path while `process.argv[1]` keeps the symlinked path. The guard saw two different strings,
concluded it was being imported rather than run, and returned without doing anything.

Every test covered the checkout shape, because that is the shape the test suite runs in. The
one environment the package actually ships into was the one nothing exercised.

## Prevention

`isDirectlyInvoked` in `src/cli.ts` compares real paths, so a symlinked entry point resolves
to the same file as its target.

The regression test constructs the symlink case specifically rather than the checkout case —
per the rule that a check needs the test where it must *speak*, not only the one where it
must pass. Fixed in `170a9f8`.

## What it cost, and what is still open

Found by installing the package into a real repository, not by any check in this one. That
is the argument for keeping a first adopter: the defect was invisible from inside the
checkout by construction.

Still open: there is no invariant forbidding a gate from reporting success without having
checked anything. `INV-INJECTED-IO` and the architecture guards would not have caught this,
and neither would a stricter type. The general form — *a gate must account for what it
examined* — is worth an invariant, and does not have one yet.
