## Why

This repository can say what its own code is for. It cannot say **which technique a
situation calls for** — and a doctrine file is where that knowledge would live if it could
be found.

Measured before this work, on the query the capability exists to answer:

```
$ kb ask "caching for a payment webhook that must not double charge"
No ranked matches ... (searched 39 entities).
Doctrine
  gates-and-automation.md   judgment-under-uncertainty.md
  module-boundaries.md      solid.md   verification-and-honesty.md
```

Five filenames, in alphabetical order, none of them relevant, and no way for the reader to
tell. The cause is in the code, not the corpus: `loadDoctrine` reads only the first `# `
heading, so a doctrine file carries no tags and no triggers; and `scoreEntity` is only ever
called on entities, so doctrine is never scored at all. `kb ctx` does not mention doctrine
in any form.

That is a Tier-1 failure in this repository's own terms. Progressive disclosure promises
~50 frontmatter tokens that let an agent decide what to read without reading anything.
Doctrine gets a filename, which decides nothing, so the agent either reads every file or
reads none. At five files it reads none.

## What

A doctrine file may carry frontmatter, and one field in it is the point:

```yaml
---
title: Idempotency and delivery semantics
tags: [messaging, retries, payments]
when:
  - a retry could apply the same effect twice
  - a consumer may receive the same message more than once
---
```

`when:` is the trigger — the signal in the situation that says *reach for this*. It is
weighted above tags and title precisely because "when to use it" is the question being
asked, and a technique's name is a poor answer to it.

- `src/tokens.ts` (new, pure): tokenising and overlap, extracted from `ask.ts` so that
  entity scoring and doctrine scoring share one implementation rather than two that drift.
- `src/doctrine.ts` (new, pure): the doctrine summary shape and `scoreDoctrine`, weighted
  `when` 4 / tags 3 / title 2 / name 1.
- `loadDoctrine` parses frontmatter when present.
- `kb ask` ranks doctrine and prints the trigger line that matched.
- `kb ctx` names doctrine whose triggers match the work item.

## Constraints honoured

- **Frontmatter is optional.** Every doctrine file that exists today has none, and each one
  still loads, still lists, and simply never outranks a file that declared a trigger. A
  format change that invalidated the corpus would be the drift this repository exists to
  abolish.
- **Ranking never hides.** Unmatched doctrine is still listed by name, as now. Invariants
  and open hazards remain unranked and returned in full — a technique is conditional, an
  invariant is not.
- **A trigger is a hint, not a claim.** `when:` asserts nothing about the code and is not an
  anchor; it is scored, never verified. See `.anchor/doctrine/tags-are-hints.md`.

## Result

```
$ kb ask "a file has grown until changes feel unsafe"

Doctrine
  module-boundaries.md - Module Boundaries
    when: a file has grown until changes feel unsafe
    .anchor/doctrine/module-boundaries.md
  5 more (no trigger matched): gates-and-automation.md, judgment-under-uncertainty.md,
                               solid.md, tags-are-hints.md, verification-and-honesty.md
```

The `discipline` pack was bumped to 1.3.0 and every doctrine file in it now declares
triggers, so this repository is the first adopter of its own mechanism rather than shipping
one it does not use.

## Note on two thresholds that came down

Adding the doctrine section pushed `ctx` past its recorded 61-line baseline, and extracting
`ctxSections` was the fix. Raising the baseline would have been loosening a threshold to hide
a failure. `render.ts` fell the same way when its doctrine block became `renderDoctrine`.

Both files then landed *under* the global 50-line limit, and the ratchet's second test — the
one that fails when a baseline is slack — correctly demanded the entries be deleted outright
rather than lowered. Two exemptions removed, none added.

## Known limit, stated rather than hidden

Lexical overlap produces false positives on single shared tokens: this work item's own title
contains the word "class", which fires SOLID's trigger about a class taking on a second
responsibility. The output prints the trigger for exactly this reason — a reader dismisses it
in one line. Precision is a corpus problem (write specific triggers) before it is a scoring
problem, and no vector index is warranted by it; the trigger in `docs/THE_ANCHORING.md`,
"Deferred, with a trigger rather than a feeling", still has not fired.
