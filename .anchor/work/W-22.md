## Why

Until now this tool could make a repository legible — what its code is for, who decided it,
how it has broken. It could not make an agent *better at engineering*, because it carried no
engineering knowledge at all. An agent working in an anchored repository knew the local
rules and nothing about the technique the situation called for.

W-20 made doctrine findable by the situation rather than by name. W-21 made it affordable to
carry. Those two are the whole precondition; without them a technique corpus is either
unreachable or a permanent tax on every cold start.

## What

Five packs, doctrine only, every file `residency: index`:

| Pack | Covers |
|---|---|
| `systems-core` | request path, traffic management, caching, database performance, distributed data |
| `systems-async` | queues, delivery semantics, idempotency, sagas, event sourcing, CQRS |
| `systems-reliability` | timeouts, retries, circuit breakers, backpressure, scaling, disaster recovery |
| `systems-platform` | containers and Kubernetes, delivery pipelines, security and identity |
| `systems-production` | observability and SLOs, concurrency and runtime, incident response |

Five rather than one, because a CLI library has no business seeding fifteen files about
Kubernetes. A pack is adopted deliberately or it is noise.

Every technique is written as a decision, not a definition — the signal that calls for it,
the cheaper thing to try first, what it costs, and how it fails. A definition is what an
agent already has; the signal is what it lacks.

## What these packs deliberately do not ship

**No invariants, and no hazards.** An invariant needs an `enforced_by` anchor and a checker
that exists in the adopting repository; `INC-0001` is the record of what happens when a pack
ships an invariant whose checker is not in the box. A hazard is a thing that happened *here*,
with a date and an anchor, and no pack can know that. Both would be claims the pack cannot
support, and this repository's whole argument is that an unsupported claim is worse than a
missing one.

So these packs ship exactly one kind of thing: doctrine, which asserts nothing about any
repository's code and is scored rather than verified.

## Result

Twenty doctrine files across five packs. Retrieval verified on a clean repository with all
five seeded — the top-ranked file was correct on every query tried:

```
$ kb ask "the webhook must not double charge when we retry it"
  delivery-semantics.md   when: a payment, charge, or transfer must not be duplicated

$ kb ask "one dependency is slow and it is taking the whole service down"
  fault-tolerance.md      when: one failing dependency is taking the whole service with it

$ kb ask "adding a cache node invalidated nearly every key"
  traffic-management.md   when: a cache node is added and nearly every key moves

$ kb ask "a query got slower as the table grew"
  database-performance.md when: a query got slower as the table grew

$ kb ask "two nodes both think they are the leader"
  distributed-data.md     when: two nodes both believe they are the leader
```

**Cost**: 160,618 bytes of corpus on disk, **14,912 bytes in tier 1** of `kb brief`. Without
W-21's `residency: index` this would have been the whole 160 KB — roughly 40,000 tokens added
to every cold start in every adopting repository, forever.

## Two things this work found

**The budget check was silent on its own case.** `checkResidentDoctrine` counted whole bodies
only, so a corpus of twenty correctly-indexed files costing 15 KB of *index entries* reported
clean. That is the failure this repository names as worse than no check: silence on exactly the
case the check exists for. It now counts what an agent actually pays — bodies and entries — and
gives a different hint depending on which dominates, because "add `residency: index`" is
useless advice to someone already fully indexed.

**`kb pack check --strict` failed clean repositories.** Recorded as `INC-0005`. The adoption
filter was disabled by a trailing `|| true` and could not have been tested while exactly one
pack existed. Both halves of that line were wrong, in opposite directions, and they cancelled.
`isAdopted` is now a pure function in `pack.ts` with a test that requires it to *exclude*
something.

## Not seeded here, deliberately

This repository adopts `discipline` and none of the `systems-*` packs. It is a CLI library with
one runtime dependency; nothing in it is served by fifteen files about Kubernetes and consensus.
Seeding them to demonstrate the feature would contradict the argument the packs are split on.
The demonstration above ran in a scratch repository instead.
