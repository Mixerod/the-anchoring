# W-16: Layer 5 Part A: the cacheable brief, delta verify, no-progress

## Goal

Implement `docs/PLAN-LAYER5.md` Part A (§3): give the tool a way to state its own context
cost and to stop paying it repeatedly.

- `kb brief [--json] [--check]` — the cold-start bundle in four volatility tiers, ordered
  most-stable-first so a change in tier 3 cannot invalidate tiers 1 and 2. Rendered from the
  corpus every time; no index, no cache.
- `kb verify --since <ref>` — findings restricted to entities the diff reaches, either
  through their own document or through an anchor. Says "no entities changed" in words.
- `kb verify --fingerprint` and no-progress detection in `kb done --check`: three runs with
  an identical finding set warn, and never fail the turn.

## Why the ordering is the feature

Prompt caching is a prefix match with at most four breakpoints. One moved byte invalidates
everything after it, silently — a cache miss announces nothing and costs roughly ten times as
much. So every count, timestamp and session note lives in tier 4, ordering is by codepoint
rather than by `readdir` or locale, and line endings are normalised so a CRLF checkout and an
LF checkout produce the same bytes.

The tool cannot observe a cache *hit* — it never calls a model. It guarantees the prefix does
not move; the harness confirms the hit by reading `usage.cache_read_input_tokens`.

## Two defects fixed in passing

- `covers()` in `done.ts` built `src//` for the directory anchor `file:src/`, so
  `INV-SECRETS-NO-LITERALS` (which holds for `file:src/`) explained nothing, and `kb done`
  reported "no document explains: src/upstream.ts" about an anchored file. Now
  `anchorCovers` in `anchors.ts`, shared with `since.ts`.
- Three byte-identical copies of FNV-1a (`guardsHash`, `upstreamHash`, `packHash`) collapsed
  into `src/fnv.ts`. A hash is a contract with files already on disk; three copies of it are
  three places to drift.
