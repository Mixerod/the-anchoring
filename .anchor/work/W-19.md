## Why

The @skills protocol (arXiv 2608.12610, `github.com/SylphAI-Inc/atskills`) delivers an agent
skill in three tiers, and only the last touches the prompt: a reference costs nothing and
evaporates with the session, a copy saved into `.atskills/` costs nothing between messages,
and a line in `.atskills/.autotrigger` buys auto-triggering at the price of permanent
residency. Reliable auto-trigger capacity is bounded — the protocol argues well under a
hundred slots per agent — so that last budget is small and is spent one line at a time by
whoever is in a hurry.

The protocol deliberately leaves one question open, because a file tree cannot answer it:
*which of those lines has the repository actually justified?* That is this repository's
question. A resident skill is a standing claim on every message, and a claim with no document
behind it is exactly what anchoring exists to catch.

Measured on the author's machine before this work: 308 resident skill descriptions, ~24,394
estimated tokens on every message, of which 3 had any evidence of ever being used.

## What

`kb skills` reads `.atskills/` and `.autotrigger`, prints the Tier 3 budget with a token
estimate, and warns about every resident skill that no entity anchors.

A skill earns residency the ordinary way: `file:.atskills/<path>` from a work item,
invariant, or decision. No new anchor form was introduced — `anchors.ts` says two forms and
deliberately no third, and a skill folder is an ordinary path on disk, so `file:` already
reaches it and `anchorCovers` already handles the trailing slash.

## Constraints honoured

- **It never writes.** `.atskills/` belongs to the host project and to the protocol, not to
  this tool. Suggested lines are printed for a human to paste, as `kb guards` prints a linter
  config rather than installing one.
- **Advisory only, always exit 0.** A gate that blocks on bookkeeping is switched off within
  a week, and then nothing is enforced.
- **The negative path is visible.** Cloud lines that cannot be weighed offline, gitignore
  patterns this reader does not implement, and lines matching no skill are each named under
  "Not counted", so the filter can be audited rather than trusted.
- **The token figure says it is an estimate** and prints its divisor. No tokenizer is called.

## Note

`src/cli-owners.ts` is a behaviour-preserving extraction, not a feature. Adding the `skills`
arm pushed `run` past its recorded size baseline, and the ratchet correctly refused. Raising
the baseline would have been loosening a threshold to hide a failure; moving the `owners` arm
into its own file — the same shape `cli-brief`, `cli-verify`, `cli-pack`, and `cli-promote`
already have — shrank `run` from 208 lines to 174, and the baseline was lowered to match.
