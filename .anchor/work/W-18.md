# W-18: Make the generated architecture checkers actually enforce something

## Goal

Close `INC-0004`: `kb guards` generated files whose every pattern matched nothing, so the
dependency matrix, the size ceilings and the pure-layer import ban were inert while three
separate gates reported success.

## What was done

- **The path bug.** A file path no longer gets a trailing slash, and a file pattern is
  anchored with `$`. Project-wide rules key off `governedPaths`, so a module added before
  anyone registers it in the matrix is still governed.
- **The matrix was wrong, not the code.** `verify`, `done`, `ask`, `why`, `ctx` and `owners`
  orchestrate I/O and are declared `app`; `infra` sits above `domain`, because an adapter
  depends on the domain it adapts. Zero source lines changed, zero violations.
- **One source of truth for lint rules.** Flat config replaces rather than merges, so the
  hand-written blocks in `eslint.config.js` were silently discarding two generated rules —
  including the ban that was supposed to keep `node:http`, `node:https` and `node:crypto` out
  of the pure core. The exemption list and the project's own selectors now live in
  `anchoring.config.json`.
- **A ratchet instead of a repeal.** 19 functions were over the 50-line limit the moment it
  began to apply. `maxFunctionLinesBaseline` fixes each offending file at its current worst,
  pinned to the line by a test, so an entry cannot be inflated and cannot outlive the
  function it excuses.
- **`kb guards --check` no longer cries wolf on Windows.** A CRLF checkout was reported as
  `hand-edited`; content comparison now ignores the line ending, and `.gitattributes` pins
  the checked-out form.

## The test that was missing

`guards-live.test.ts` asserts what ESLint *applies* rather than what the generator emits.
Every gate that failed here failed the same way: it asked a question it could answer without
touching the thing that was broken.
